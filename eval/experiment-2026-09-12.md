# 案例实验：无 Skill / 有 Skill 单次对照（2026-09-12）

> **结论先行**：本次对照**没有显示高风险召回率上的增益**——两组都识别出了全部 7 项预埋高风险。
> 有 Skill 组的可测量差异在另外三处：**证据可追溯率 100% vs 0%**、**完成率 是 vs 否**、
> 以及**结论可被机器验证 vs 只能人工阅读**。按计划文档的约定，
> 对照未显示增益时只公布原始结果，**不宣称 Skill 优于普通提示词**。

## 五、结论

1. **判断准确性上，本次对照未显示增益。** 两组都识别出了全部 14 项、命中全部 7 项预埋高风险，均无误报。
   按计划文档约定，**不宣称 Skill 优于普通提示词**。
2. **真正的差异在"可验证性"而非"召回率"。** 无 Skill 组自己也承认无法提供可复核的定位信息、
   也无法确认覆盖范围；有 Skill 组的每条判断都通过了验证器回溯（数值指向候选 `number_id`，
   引用指向真实 `paragraph_id` 与页码），因此证据可追溯率为 100%。
3. **完成率与可复现性的差异是硬性的、不可争议的。** 无 Skill 组没有产出任何可存档、可复跑的产物；
   有 Skill 组产出了带时间戳的运行目录、manifest 哈希记录与正式报告。
4. **代价是有 Skill 组更慢**（约 81 秒 vs 25 秒），主要开销在确定性解析与逐条证据定位。

## 六、局限（必读）

本记录的效力边界如下，任何引用都应连同本节一起引用：

1. **这是单次案例实验，不是稳定性评测。** 1 次运行、1 个模型、1 套全合成数据。
   计划文档明确要求：结果统一标记为案例实验，不能称为稳定性评测。
2. **无 Skill 组存在明显的设计者/执行者偏差。** 两组由同一个模型在同一会话中先后执行，
   且执行者在执行无 Skill 组时已经知道 Demo 的结构与预埋设计。因此无 Skill 组的
   14/14 属于**上限估计**，真实的无 Skill 表现很可能更低。
3. **无 Skill 组的评分是人工判定的。** 判定标准是"实质判断是否与标准答案一致"，
   而该组并未使用固定判断分类，表述与标准答案的分类名之间需要人工映射，存在解释空间。
4. **合成数据的表现不能代表真实论文。** 本 Demo 只有 1 张表、5 条引用、5 篇参考文献；
   真实论文的数值密度、表述隐晦程度与参考文献长度都远高于此。
5. **本实验没有覆盖未提供的参考文献全文。** 第 5 条引用的正确表现是"如实报告全文不可用"，
   而不是"核查了它的内容"。
